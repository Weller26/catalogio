# Отчёт: Развёртывание Catalogio в Kubernetes


## 1. Абстракции Kubernetes, использованные для запуска

- Namespace (catalogio) — изолированное пространство имён. Отделяет все ресурсы проекта от стандартных и системных сервисов кластера, позволяя управлять ими как единым целым.
- ConfigMap (catalogio-config, migrations-files) — хранилище открытых настроек. В нём лежат параметры подключения (хост postgres, порт 5432, имя БД), а также SQL-файлы миграций, которые монтируются в контейнер в виде папки.
- Secret (catalogio-secrets) — хранилище конфиденциальных данных (пароль к базе данных и ключ JWT_SECRET), создаваемое из закрытого .env.secret файла без попадания в Git.
- PersistentVolumeClaim (postgres-pvc) — запрос постоянного диска для PostgreSQL. Обеспечивает сохранность данных при перезапуске пода базы.
- Deployment (postgres, catalogio-app) — описывает желаемое состояние подов: количество реплик, образы контейнеров, переменные окружения и лимиты ресурсов. Автоматически перезапускает поды при сбоях.
- Job (catalogio-migrate) — одноразовая задача. Запускает контейнер с утилитой миграций, применяет схему базы данных и сразу корректно завершает свою работу.
- Service:
    - postgres (внутренний ClusterIP) — предоставляет постоянное сетевое имя postgres и порт 5432 для обращения к базе данных внутри кластера.
    - catalogio-service (внешний NodePort) — пробрасывает порт веб-приложения наружу, делая его доступным для открытия в браузере.

## 2. Как сервисы взаимодействуют между собой

- Обнаружение сервисов (Service Discovery): Благодаря внутреннему DNS кластера приложения не привязаны к динамическим IP-адресам подов. И веб-сервер catalogio-app, и задача миграций обращаются к базе данных напрямую по доменному имени сервиса — postgres:5432.
- Порядок работы:
    - Сначала запускается под PostgreSQL и монтирует к себе постоянный диск postgres-pvc.
    - Затем запускается Job миграций, берёт SQL-скрипты из ConfigMap, накатывает таблицы в базу и останавливается.
    - После этого запускается веб-приложение catalogio-app, подключается к уже готовой БД через пул соединений и начинает обрабатывать запросы.
- Обработка запросов: Пользователь переходит по внешнему адресу сервиса catalogio-service, сервис перенаправляет HTTP-трафик на порт 8080 пода catalogio-app, а бэкенд обращается к базе данных через внутренний сервис postgres.
- Сетевая безопасность: База данных PostgreSQL полностью закрыта от внешнего мира и принимает подключения только от сервисов внутри пространства имён catalogio.
