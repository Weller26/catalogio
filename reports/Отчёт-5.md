# SLA, SLO, SLI

## Стек и архитектура мониторинга

- **Язык**: Go.
- **TSDB**: VictoriaMetrics Single.
- **Визуализация**: VictoriaMetrics UI (`vmui`).
- **Модель мониторинга**: Pull-модель (скрейпинг через внутренний эндпоинт `/metrics`).
- **Генератор нагрузки**: Синтетический пробер ([scripts/prober.sh](scripts/prober.sh)).

## Выбранные метрики

Для расчёта доступности и качества работы сервиса выбраны 3 метрики:

1. `http_requests_total` (CounterVec, метки: `method`, `path`, `status`).  
  Техническая метрика доступности сервиса (Availability). Отражает общее количество входящих HTTP-запросов и распределение их HTTP-кодов ответа. Позволяет выявлять сбои приложения (коды `5xx`).
2. `http_requests_duration_seconds` (HistogramVec, метки: `method`, `path`, `status`).  
  Техническая метрика задержки обработки запросов (Latency). Фиксирует распределение времени ответа сервиса по бакетам гистограммы. Позволяет контролировать время ожидания клиентов.
3. `http_requests_total` для операций изменения каталога (Counter).  
  Бизнес-метрика доступности ключевых доменных операций. Отражает успешность выполнения изменений каталога (создание `POST`, обновление `PUT`, удаление `DELETE` записей по `/api/v1/items`). Сбой в этих операциях означает невозможность для пользователей управлять своими записями.

## Формулировки SLI, SLO и SLA

### Терминология

Выбранный подход: RBSLO (Request-Based SLO).

### Индикатор 1: Общая доступность HTTP-запросов (HTTP Availability)

- **Подход**: RBSLO (Request-Based).
- **Формулировка SLI**: Доля HTTP-запросов, завершившихся без внутренних ошибок сервера (все статусы, кроме `5xx`), за скользящее окно в 1 минуту:
  $$\text{SLI}_{\text{avail}} = \frac{\sum \text{Requests}_{\text{status} \ne 5..}}{\sum \text{Requests}_{\text{total}}} \times 100\%$$
- **Формула расчета (PromQL)**:
  ```promql
  (sum(rate(http_requests_total{status!~"5.."}[1m])) / sum(rate(http_requests_total[1m]))) * 100
  ```
- **SLO**: $\text{SLI}_{\text{avail}} \ge 99.0\%$ за скользящее окно в 1 минуту (не более 1 ошибки на 200 запросов).
- **SLA**: $\text{SLI}_{\text{avail}} \ge 95.0\%$ в месяц.

### Индикатор 2: Задержка обработки HTTP-запросов (HTTP Latency)

- **Подход**: RBSLO (Request-Based).
- **Формулировка SLI**: Доля входящих HTTP-запросов за последнюю 1 минуту, обработанных быстрее $100\text{ мс}$ (`le="0.1"`):
  $$\text{SLI}_{\text{latency}} = \frac{\sum \text{Requests}_{\text{duration} \le 0.1\text{s}}}{\sum \text{Requests}_{\text{total}}} \times 100\%$$
- **Формула расчета (PromQL)**:
  ```promql
  (sum(rate(http_requests_duration_seconds_bucket{le="0.1"}[1m])) / sum(rate(http_requests_duration_seconds_count[1m]))) * 100
  ```
- **SLO**: $\text{SLI}_{\text{latency}} \ge 95.0\%$ всех запросов укладываются в $100\text{ мс}$.
- **SLA**: Не менее $90.0\%$ запросов должны укладываться в $250\text{ мс}$ (`le="0.25"`).

### Индикатор 3: Доступность операций изменения каталога

- **Подход**: **RBSLO** (Request-Based).
- **Формулировка SLI**: Доля операций модификации каталога (создание `POST`, обновление `PUT`, удаление `DELETE` записей по пути `/api/v1/items`), завершившихся без ошибок сервера (все статусы, кроме `5xx`) за скользящее окно в 1 минуту:
  $$\text{SLI}_{\text{modification}} = \frac{\sum \text{Requests}_{\text{modification}, \text{status} \ne 5..}}{\sum \text{Requests}_{\text{modification}, \text{total}}} \times 100\%$$
- **Формула расчета (PromQL)**:
  ```promql
  (sum(rate(http_requests_total{method=~"POST|PUT|DELETE", path=~".*/items.*", status!~"5.."}[1m])) / sum(rate(http_requests_total{method=~"POST|PUT|DELETE", path=~".*/items.*"}[1m]))) * 100
  ```
- **SLO**: $\text{SLI}_{\text{modification}} \ge 99.0\%$ (операции управления записями критичны для функционирования приложения).
- **SLA**: $\text{SLI}_{\text{modification}} \ge 95.0\%$.

### Общий SLA приложения

Приложение удовлетворяет SLA, если одновременно выполняются условия:
1. $\text{SLI}_{\text{avail}} \ge 95.0\%$ (общая доступность HTTP).
2. $\text{SLI}_{\text{latency}} \ge 90.0\%$ для порога $250\text{ мс}$ (скорость отклика).
3. $\text{SLI}_{\text{modification}} \ge 95.0\%$ (успешность бизнес-операций с каталогом).

## Пробер

Для тестирования приложения и формирования постоянного потока метрик для вычисления `rate` в скользящих окнах был реализован скрипт-пробер [`scripts/prober.sh`](scripts/prober.sh).

Пробер выполняет циклические синтетические проверки каждые 1–2 секунды:
- `GET /catalog.html` — проверка доступности веб-интерфейса и статических ресурсов.
- `POST /api/v1/auth/login` — аутентификация для получения токена доступа.
- `POST /api/v1/items`, `PUT /api/v1/items/{id}`, `DELETE /api/v1/items/{id}` — выполнение операций модификации каталога (Write Path).
- `GET /api/v1/items` — проверка работы чтения каталога (Read Path).

## Описание изменений приложения для демонстрации

Для демонстрации деградации метрик и нарушения SLO/SLA на скринкасте в приложение были внесены изменения:

### Архитектурное разделение портов (Public / Internal)

В целях безопасности технические эндпоинты отделены от пользовательских:
- **Порт 8080 (Public Router)**: пользовательские API-методы (`/api/v1/...`), HTML, CSS, JSON. Проброшен наружу через `Service`.
- **Порт 8081 (Internal Router)**: технический сервер. Содержит эндпоинты `/metrics`, `/healthz` и эндпоинты управления внедрением `/api/v1/chaos/*`. Не проброшен наружу.

### Модуль Chaos Injection (`internal/httpapi/chaos.go`)
Модуль искусственного замедления и поломки сервера:
- `chaosDelayMs` — задержка запросов.
- `chaosErrorPercent` — процент вероятности генерации ошибки `500 Internal Server Error`.
- `ChaosMiddleware` — перехватывает публичные запросы к порту 8080 и вносит задержку или возвращает HTTP 500, благодаря чему метрики `http_requests_duration_seconds` и `http_requests_total` фиксируют ухудшение качества обслуживания.

### Эндпоинты для управления
- `POST /api/v1/chaos/slow?ms=n` — включение задержки в n мс (эмуляция нарушения Latency SLO).
- `POST /api/v1/chaos/fail?percent=n` — генерация n% ошибок 500 (эмуляция нарушения Availability SLO/SLA).
- `POST /api/v1/chaos/reset` — сброс сбоев и возврат к штатному режиму.
- `GET /api/v1/chaos/status` — просмотр текущих параметров сбоев.
